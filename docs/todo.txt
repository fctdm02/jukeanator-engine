MOBILE/WEB REST API DESIGN NOTES
================================
Done so far:
- DTOs are Java records.
- Insufficient credits return HTTP 402 (Payment Required) via GlobalExceptionHandler.

Still open:

1: Money as minor units. Use a priceMinor (long) field for credit pack prices instead of
   BigDecimal/double; format on the client.

2: Idempotency on credit purchases. Accept an Idempotency-Key header on the Add Funds/purchase
   endpoint so mobile retries are de-duplicated without double-charging.

3: Pagination. Wrap Spring's Page<T> in a lean PageResponse<T> record for paged endpoints
   (for example the artist list) so Spring's PageImpl JSON shape is not exposed.

4: Cover art URLs. Return either a CDN URL or null, letting the client render a gradient
   placeholder when there is no art.

5: Genre slugs. Send a stable slug (ROCK, NEW_RELEASES) plus a display label and two hex colors
   per genre tile, so the mobile theme is data-driven instead of a hard-coded palette.

6: Live updates. Push queue and now-playing changes to all connected devices over STOMP
   (@MessageMapping controllers); REST endpoints publish to the topic after every mutation.

7: Auth. Patrons are anonymous but persistent (a device-bound JWT). Staff get a STAFF role that
   unlocks queue skip and future admin endpoints. Resolve the venue/location on the server so one
   location's queue cannot leak into another.

8: OpenAPI spec. Publish one so the mobile app can consume generated TypeScript clients.
